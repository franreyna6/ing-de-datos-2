## Hipotesis
El servidor ya tiene un token de administracion (creado en el Hito 8) y el archivo local se perdio.
'influxdb3 create token --admin' sin token previo falla; la salida del README del Hito 8
(limpieza --datos) borraria los datos, lo que el Hito 11 prohibe.

## Prueba / correccion (reversible, sin borrar datos)
InfluxDB 3 Core ofrece un endpoint de recuperacion del token de administracion
(--admin-token-recovery-http-bind / INFLUXDB3_ADMIN_TOKEN_RECOVERY_HTTP_BIND_ADDR).
1. Se recreo el contenedor UNA vez con un override temporal FUERA del repositorio que solo
   agrega INFLUXDB3_ADMIN_TOKEN_RECOVERY_HTTP_BIND_ADDR=127.0.0.1:8182 (escucha DENTRO del
   contenedor; ese puerto no se publica). Montaje de datos verificado igual antes y despues:
   C:\Users\<usuario>/docker/data/influxdb -> /var/lib/influxdb3/data
2. echo yes | docker exec -i fixture2030-influxdb influxdb3 create token --admin --regenerate \
       --host http://127.0.0.1:8182   > (salida filtrada: solo el token, a .influxdb3-token)
   token guardado (92 caracteres)
3. Se recreo el contenedor con el docker-compose.yml ORIGINAL (sin el endpoint de recuperacion).

## Resultado
$ influxdb3 show databases     (con el token nuevo)
| _internal | fixture2030_historico | fixture2030_resumen | fixture2030_vivo |
  -> autorizacion OK, datos previos intactos (las 3 bases del equipo siguen presentes)
